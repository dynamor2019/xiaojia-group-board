# 小贾AI群看板

**把 QQ 和微信群里所有「@所有人」的喊话，收成一块左右两列、能标记完成、能退订群的面板。**

不用天天翻几十个群，也不会为了这个去跑什么机器人把号跑封。

## 先搞清楚启动顺序（看这一段就够了）

**一句话：项目先起，QQ 后起，而且 QQ 由脚本自己拉 —— 你不用手动开，微信全程不用动。**

1. **先退出 QQ**（如果它正开着）
2. **双击「启动看板.cmd」** —— 看板起来，这一步跟 QQ 完全无关
3. **点右上角「刷新数据」** —— 脚本用 NapCat 拉起 QQ → 抓取 → 自动关掉
4. **想继续用 QQ，自己再打开它** —— 抓完被关掉是设计，不是崩溃

### 为什么「QQ 开着」就抓不到 QQ

NapCat 是把自己注入到一个**新创建**的 QQ 进程里去的。  
如果你的 QQ 已经开着，它就注不进去 —— 这时候脚本会**主动跳过 QQ、只抓微信**，  
而不是去杀掉你正在用的 QQ。

所以：**「QQ 现在开着」和「这次能抓 QQ」是互斥的**。不怪脚本，这是机制决定的。

> **先说一句风险**：QQ 侧要登录、要注入，所以存在账号被风控的可能（有人真的遇到过限制登录）。  
> 微信侧不登录不注入，没这个问题。决定要用 QQ 侧之前，建议先看  
> 「[会不会把号跑封](#会不会把号跑封)」和「[真被 QQ 限制了怎么办](#真被-qq-限制了怎么办)」。

### 扫码：只需要一次

脚本是用 `-q <你的QQ号>` 做**快速登录**的，靠的是本机已有的登录态：

| 情况                          | 要不要扫码          |
| --------------------------- | -------------- |
| 这台机器用该 QQ 登录过，且没清过 QQ 数据目录  | **不用**，静默登录    |
| 第一次用 / 换电脑 / 换 QQ 号 / 登录态失效 | **扫一次**，之后一直免扫 |

> **「免扫码」免的是扫码，不是 NapCat。** 登录态存在 **QQ 自己的数据目录**里  
> （`Documents\Tencent Files\` 下），不在 NapCat 手里 ——  
> `napcat\config\napcat_<QQ号>.json` 只存日志级别、hook 开关这类设置，**没有密码也没有令牌**。  
> 每次抓取仍然要 NapCat 注入到 QQ 进程里，因为它是**取消息的通道**，  
> 不是"帮你截一次登录信息就完事"的工具。这条也决定了风控风险：每天跑一次，  
> 就是每天登录一次。

时间也够：脚本拉起 QQ 后先等 8 秒，再给 NapCat 最多 120 秒连上来，  
你有大约两分钟扫码。真超了日志会写「等了 120 秒 NapCat 仍未连接」，QQ 也会被自动收掉，  
重来一次就行。

> 如果二维码一直没出现，最稳的办法：手动打开 QQ 正常登录一次（勾上自动登录），  
> 再关掉 QQ，然后回来点「刷新数据」。

### 微信那边呢

不用管。微信开着就行，你正常聊天，脚本读的是磁盘上的库，全程不重启、不退出。

## 它解决什么

你在 30 个群里，每条重要通知都是 `@所有人`。它们散落在各个 App、各个群、各个时间点，  
于是你要么天天爬楼，要么直接漏掉「11月3日17:00 前完成评教」这种要命的一句。

这个工具做三件事：

1. **抓** —— 从本机 QQ / 微信的本地数据里，把带 `@所有人`、`@全体成员` 的消息挑出来
2. **排** —— 抠出截止时间，按「今天 / 明天 / N 天后 / 无期限」排好，过期的自动隐藏
3. **看** —— 生成一块 HTML 看板，左 QQ、右微信，两个通道绝不混排

看板上你可以：搜索、按群筛选、只看带截止时间的、点「标记完成」、点 `✕` **取消关注某个群**  
（退订后爬虫直接跳过它，彻底不再扫描）。

## 会不会把号跑封

先把话说在前面：**会，概率不高，但确实发生过。**  
有用户在另一台电脑上跑完这一套，QQ 被限制登录了。所以这一节不写"保证安全"，  
而是讲清楚**风险在哪、怎么压到最低、真出事了怎么办**。

所有「群消息聚合」工具翻车，基本都翻在这两件事上：**改客户端** 和 **模拟登录**。  
这个项目两条都不碰 —— 但这只能说明风险比别人低，**没有哪个方案能承诺 100% 不被风控**。  
账号是你的，判定权在腾讯手里，不在代码手里。

### QQ：不碰登录，只走本地 OneBot

QQ 侧用 [NapCat](https://github.com/NapNeko/NapCatQQ) —— 它是一个**本地**的 OneBot 实现，  
挂在你自己已经登录的 QQ 进程上，消息从本机 WebSocket 出，不经过任何第三方服务器。

关键在于节奏：

```
启动 QQ（快速登录） → 抓（本地 WS，只读） → 抓完立刻退出 QQ
```

NapCat 只能注入**新创建**的进程，所以每天跑的时候先拉起一个干净的 QQ，  
抓完就关掉，回到你平时手动登录的状态。全程不发消息、不加好友、不拉群、不点同意，  
行为上跟「你自己打开 QQ 翻了一下群」没有区别。

### 微信：根本不用退出

微信的数据库就在磁盘上，只要拿到密钥就能**离线**解密 —— 不需要保持进程、不需要注入。

```
只读扫描微信进程内存取出密钥 → 离线解密数据库副本 → SQLite 查询 → 完成
```

- 对微信进程只做 `PROCESS_VM_READ`（只读），**不写内存、不注入 DLL、不挂调试器**
- 不修改微信安装目录，不碰登录态
- 微信可以一直开着，你正常聊天，后台 6 秒跑完

密钥提取这部分没有自己造轮子，直接用了  
[wcdb-key-tool](https://github.com/TANGandXUE/wcdb-key-tool)（MIT），  
它解决了微信 4.1+ 不再缓存明文密钥的问题。代码已 vendor 到 `app/vendor/wcdb-key-tool/`。

### 两个通道的差异，一张表

|          | QQ                    | 微信                  |
| -------- | --------------------- | ------------------- |
| 接入方式     | NapCat + OneBot 反向 WS | 本地 SQLCipher 库离线解密  |
| 需要退出客户端吗 | **需要**（抓完即退）          | **完全不用**，一直在线       |
| 每次耗时     | 约 40–90 秒（含启动 QQ）     | 约 6 秒（增量）           |
| 首次额外开销   | 下 NapCat（点一下就自动下）     | 取密钥 12 秒 + 首次解密 7 秒 |
| 抓不到时     | QQ 已开着 → 那一路自动跳过      | 微信没开 + 有旧密钥 → 照样能抓  |

> 说人话：微信是「磁盘上有，随时能读」；QQ 是「只能在它自己新建进程的那一刻读」。  
> 所以一个能常驻，一个只能速战速决。

### 真被 QQ 限制了怎么办

症状长这样：登录时提示「账号存在安全风险」「当前登录环境异常」，要求短信或人脸验证，  
严重的直接限制登录几天。

解决方案：

**在手机上装「国家网络身份认证」App，完成网证核验后再登录，限制就解开了**。  
这条是**用户经验，不是腾讯官方口径**，不保证人人有效 —— 官方渠道尝试走不通

恢复之后，这几条比什么技巧都管用：

- **一个号固定在一台电脑上跑。** 今天这台、明天那台，是最容易被判「异地异常」的行为
- **别一天跑十几次。** 任务计划一天一次就够，抓完就把 QQ 关掉
- 刚被限制过的那几天停一停，别马上又跑，容易二次判定
- 换电脑 / 换网络（比如从家搬到公司）之后，先手动登几天 QQ 再开自动抓

> 怕影响主号，就把 `qq.enabled` 关掉，只用微信侧；或者换一个不常用的小号来跑 QQ。  
> 微信侧不注入、不登录，没有这个问题。

## 快速开始

**环境**：Windows 10/11 + Python 3.10 及以上（装的时候记得勾 `Add python.exe to PATH`）

只想看微信的话，装完 Python 就完事了。要跑 QQ 那一路，还有一个前置条件：  
**QQ 得是 NT 版 9.9.27 以上**（构建号 ≥ 40768），低了 NapCat 起不来。  
版本对不对，点一次「环境体检」就能看到。

```bat
git clone https://github.com/dynamor2019/xiaojia-group-board.git
cd xiaojia-group-board
```

然后**双击根目录的 `启动看板.cmd`** —— 就这一个入口，其余全在网页里。

那个黑色窗口**几秒后自己就没了，这是对的**：服务已经转到后台，窗口关掉不影响看板。  
再双击一次也不会起第二份，只是把浏览器重新打开。

第一次启动会自动做三件事：

1. 没有 `config.json` 就生成一份（想改参数编辑它就行）
2. 缺 Python 依赖就自动 `pip install`（只有一个 `websockets`）
3. 在后台拉起看板服务并打开浏览器

> **想停掉？** 点页面最下方的「停止看板服务」。  
> 万一没起来，那个黑窗口会**停住**并把日志尾巴打出来（而不是一闪而过），  
> 完整日志在 `data/logs/看板.log`。

打开后右上角有三个按钮：

| 按钮         | 作用                                                                       |
| ---------- | ------------------------------------------------------------------------ |
| **↻ 刷新数据** | 立刻抓一次（微信 + QQ），日志实时滚在下方黑框里，完事自动重载看板                                      |
| **环境体检**   | 逐项检查 Python / 依赖 / NapCat / QQ 号 / 微信数据目录 / 密钥；缺 NapCat 和缺依赖都能在面板里点一下自动装 |
| **看示例**    | 切到 `demo/` 的假数据看效果，不动你的真实群                                               |

> 第一次点「刷新数据」之前，**记得先把 QQ 退掉** —— 不然 QQ 那一路会被跳过，  
> 原因见上面「[先搞清楚启动顺序](#先搞清楚启动顺序看这一段就够了)」。

### 想配 QQ 的话，还差一步

**微信侧开箱即用**（目录自动探测），不用任何额外准备。

QQ 侧需要 [NapCat](https://github.com/NapNeko/NapCatQQ)，**不用手动去 GitHub 下载**：

1. 双击「启动看板.cmd」，点右上角「环境体检」
2. 看到 `NapCat 没找到 …` 那行，**点它下面的「⬇ 下载 NapCat」** —— 自动下 34 MB、  
   解压到项目下的 `napcat\`，进度会实时打在面板里，装完自动复查变绿
3. 在 `config.json` 里填上 `qq.uin`
4. 点一次「刷新数据」，QQ 被拉起来后扫码（就这一次，之后免扫码）

也支持命令行，适合没有浏览器的场合：

```bat
python app\launch.py napcat
```

> **下不动怎么办？** 公司网络／代理挡住 GitHub 时，自动下载会失败并打印日志。  
> 手动方案一样简单：去 [Releases](https://github.com/NapNeko/NapCatQQ/releases) 下  
> `NapCat.Shell.zip`（**别下 OneKey，那个要人点**），把解压出来的文件**全部**放进  
> 体检提示的那个 `napcat` 目录，再点一次「环境体检」即可。
>
> 重复下载不会顶掉你的登录状态 —— 解压时会跳过 `napcat\config\` 里已有的文件，  
> 所以升级 NapCat 之后不用重新扫码。

### NapCat 对 QQ 版本有要求

> ⚠️ 这一条不看，最容易出现「昨天还能抓、今天就废了」。

NapCat 是**挂在 QQ 进程里**干活的，QQ 每升一个版本，它的注入方式就可能失效。  
所以它有两道门槛：

|         | 要求                                     | 违反了会怎样               |
| ------- | -------------------------------------- | -------------------- |
| **硬门槛** | QQ 必须是 **NT 版 9.9.27 以上**（构建号 ≥ 40768） | 压根起不来，日志报加载失败        |
| **软门槛** | QQ 最好接近 **NapCat 发布时适配的那一版**           | 能启动，但可能登不上、或一条消息都抓不到 |

**最容易踩的坑是"QQ 自动升级"** —— 昨天还好好的，今天开机 QQ 自己悄悄更到最新版，  
NapCat 就加载失败了。这不是你配错了，是它追不上新版本。

遇到这种情况，按顺序试：

1. **更新 NapCat**（首选）：点「环境体检」里 NapCat 那一行重新下载，或跑  
   `python app\launch.py napcat`。登录态会保留，不用重新扫码
2. 还是不行就等一两天 —— NapCat 通常很快就跟进适配
3. 急着用的话把 QQ 退回上一版：安装目录的 `versions\` 里留着旧版本，  
   `versions\config.json` 里 `curVersion` / `prevVersion` 指的就是这两个  
   （改之前先把 `config.json` 复制一份，改坏了能还原）

**怎么查版本**：点「环境体检」，会直接显示一行 `QQ 版本 9.9.36-53644`。  
低于 `9.9.27`（构建 `40768`）它会标黄，提醒你先升级 QQ。

> 本机实测组合：QQ `9.9.36-53644` + NapCat `v4.18.41`，正常。

> 不想碰 QQ 就把 `config.json` 里的 `qq.enabled` 改成 `false`，只当微信看板用，一样好用。  
> 更省事的办法是看板右上角的「数据源」直接点开关，见下一节。

> **为什么一个"看板"要起个本地服务？** 因为浏览器不允许网页直接写磁盘文件，  
> 而「取消关注某个群」「标记已完成」必须落到 `data/board_state.json`，爬虫下次才知道要跳过。  
> 这个服务只用 Python 标准库，跑在 `127.0.0.1:8766`，只监听本机，不对外开端口。

## 「数据源」：位置、账号、开关

看板右上角有个 **数据源** 按钮，QQ 和微信两边的读不读、读谁，全在这一个面板里改，不用去动 `config.json`。

**开关** —— 每个通道前面一个开关。关掉 QQ 就彻底不启动 NapCat、不碰 QQ 进程，
只留微信那一路。心里没底、或者号刚被限制过，先关一两天是合理的选择。

**位置** —— 程序会自己找常见安装位置，找不到才需要你填：

| 通道  | 找的是什么                     | 自动找的地方                                        | 找不到怎么办                                        |
| --- | ------------------------- | --------------------------------------------- | --------------------------------------------- |
| QQ  | `QQ.exe` 本身               | 注册表里的安装目录、`C:\`/`D:\` 下的 `Tencent\QQNT`       | 面板里点「选…」，把 `QQ.exe` 的完整路径粘进去                  |
| 微信  | 账号下的 `db_storage` 文件夹（里面要有 `message`） | `%APPDATA%\Tencent\xwechat\config\*.ini` 里记的数据根 | 面板里点「选…」，把那个文件夹的完整路径粘进去                        |

**多个账号会当场问你** —— 这台机器登录过几个微信号（或几个 QQ 号）时，下拉框**故意留空**，
不替你猜。选错了不会报错，只会抓出来一片空，那比报错更难查。

微信那边每一行都标了 `账号 · 几个库 · 最近更新时间`，挑最近在用的那个就行。
同一个号在换盘前的旧位置还有一份副本时，只算一个号，不会拿这个来烦你。

> 位置信息只写在本机 `config.json`，不上传任何地方。改完点 **保存**，
> 再点一次 **↻ 刷新数据**，才会按新设置去读 —— 保存本身不会触发抓取。

## 自动更新

看板**每天自己问一次** GitHub 有没有新提交（不弹窗，只是问一下，正常几百毫秒）。  
有更新的话，页面顶上会出现一条绿色提示条：

```
↑ 有新版本   远端 72f5bc73 · 10-30 12:06，你这里是 1.1.0（2e7ce2ed）
                              [更新了什么]  [立即更新]  [✕]
```

点「更新了什么」先看改动清单（就是提交说明，一条一行），觉得合适再点「立即更新」。  
**更新是原地完成的**，不用你去 GitHub 下载：

- 你是 `git clone` 下来的 → 走 `git pull --ff-only`，只传增量
- 你是下 zip 解压的（没有 `.git`）→ 下载整包覆盖，只覆盖程序文件
- git 拉不动（SSH 没配 key、公司网络挡 22 端口）→ **自动退回整包下载**

三种方式都**只动程序文件**，`config.json`、`data/`、`napcat/`、以及解密出来的明文库  
一概不碰 —— 这也是为什么更新可以放心点。更完页面会自己重启（关掉旧进程、用同一个端口  
起新的），你什么都不用做。

嫌烦就点 `✕`：那条更新不再提醒，等下一次真有新提交才会再冒出来。

## 定时跑

想每天自动刷新，用 Windows 任务计划，填三格：

```
程序或脚本： C:\Program Files\Python311\python.exe
添加参数：   -X utf8 app\launch.py update
起始于：     C:\path\to\xiaojia-group-board
```

注意两点：

- **QQ 侧如果当时 QQ 已开着，那一路会跳过**（NapCat 需要一个新进程），微信侧不受影响，  
  这种跳过不算失败，返回码是 0
- 看板常驻不用管：把 `启动看板.cmd` 的快捷方式放进启动文件夹，之后打开  
  `http://127.0.0.1:8766/` 就行

## 目录结构

根目录只有 4 样东西：**一个 .cmd、一份 README、一份配置、一块看板**，代码全在 `app/` 里。

```
xiaojia-group-board/
├─ 启动看板.cmd          ← 唯一入口，双击它就够了
├─ config.json           ← 自动生成，想改参数编辑它
├─ 小贾AI群看板.html      ← 自动生成的看板
├─ app/                  ← 全部代码
│  ├─ launch.py          启动 + 自检 + 自动装依赖
│  ├─ serve_board.py     本地服务：看板 + 刷新 + 体检（只用标准库）
│  ├─ settings.py        配置读取与路径约定
│  ├─ update_wx.py       微信一键：取密钥 → 解密 → 抓 → 重出看板
│  ├─ wx_crawl.py        从解密后的微信库里抠 @所有人
│  ├─ auto.py            QQ 一键：启动 → 抓 → 退出
│  ├─ crawl_ws.py        通过 OneBot 反向 WS 抓 QQ 群消息
│  ├─ digest.py          规则式抠截止时间、判断要不要动手
│  ├─ report.py          渲染看板（自包含单 HTML，图也内嵌）
│  ├─ board_state.py     已完成 / 已退订群的唯一真相
│  ├─ napcat_setup.py    自动下载 / 升级 NapCat
│  └─ vendor/            微信密钥提取（MIT，第三方）
├─ napcat/               ← 一键下载的 NapCat（用完才有）
├─ data/                 ← 抓取结果、状态、日志
├─ assets/               logo、截图
├─ demo/                 示例数据
└─ docs/                 技术原理
```

## 常见问题

**Q：微信那一侧提示「一个库都没解开」**  
密钥失效了（换了账号、微信重建了库）。用 `python app/update_wx.py --force` 重新提取。  
前提是微信**正在运行**，密钥只能从活动进程里取。

**Q：微信必须开着才能跑吗？**  
不需要。密钥取到一次会存下来，之后微信关着也能离线解密。  
但新消息要等微信把消息写进库，所以想抓最新的还是让微信开着顺便聊。

**Q：QQ 侧一条都没抓到**  
按顺序排查：① 体检里 NapCat 是不是绿的，没绿就点「⬇ 下载 NapCat」；② QQ 号填了没；  
③ 跑的时候 QQ 是不是已经开着（那就跳过了）；④ 群里最近真的没有 `@所有人`；  
⑤ 体检里那行 `QQ 版本` 有没有标黄。

**Q：昨天还能抓，今天 QQ 一条都没了**  
九成是 **QQ 自动升级了**，NapCat 追不上新版本。先更新 NapCat（体检面板里重新下载，  
登录态会保留），不行就等一两天。详见上面「[NapCat 对 QQ 版本有要求](#napcat-对-qq-版本有要求)」。

**Q：QQ 被限制了怎么恢复**  
先走 QQ 官方验证和腾讯客服申诉，再考虑其他办法 —— 完整步骤写在  
「[真被 QQ 限制了怎么办](#真被-qq-限制了怎么办)」。恢复之后建议一个号只在一台电脑上跑，  
别多机轮换。

**Q：NapCat 自动下载失败**  
GitHub 连不上（代理 / 公司网络）。面板会打印失败原因，并给出手动方案：  
去 [Releases](https://github.com/NapNeko/NapCatQQ/releases) 下 `NapCat.Shell.zip`，  
解压出来的文件全部丢进体检提示的那个 `napcat` 目录即可。选 Shell 版，**别选 OneKey**。

**Q：有的群先发通知、再单独发一条 `@所有人`，看板能对上吗？**  
能，而且**两个方向都管** —— 正文可能在前（先写通知再补喊一声），也可能在后  
（先喊人、同一人紧接着把正文贴出来）。哪边有就接哪边，两边都有就合并。  
抓到的如果是"光秃秃一条 `@所有人`"，会补上正文并标注来源，比如  
「↑ 这条只发了 @所有人，正文取自上下文 · 同一人 · 1 分钟前」——  
标出来是因为这段字**不在原消息里**，得让你知道。

判定不是无脑取前后：往前那侧先过"像不像通知"（时间、截止、请/务必…）再按  
「同一人、时间近、够长」加权；往后那侧**只认同一个人**紧接着发的（别人插话不算）。  
闲聊和疑问句会被排除，因为本机统计里七成纯喊话的上一条都是无关聊天。


实在找不到的**不硬凑**——看板不显示，但在页头报数
（"N 条只喊了 @所有人、上下文也找不到正文，已隐藏"），不会静默吞掉。

**Q：点了「完成」，下次刷新它去哪了？**
收起来了，不再显示 —— 这是故意的。标记过的条目**直接不写进看板**（不是 CSS 藏起来），
所以搜索、筛选、统计都碰不到它，页面也小一圈。页头会报数：
「14 条已标记完成，17 条已过期，……，已隐藏」。

**群不会跟着消失**：如果一个群的 `@所有人` 全被你标成完成，它会变成一张虚线卡片，
写着「N 条已完成 · 已收起」，点开还有一句说明。这样你看到的是"我标记过了"，
而不是"群怎么少了"。

点岔了想找回来：先点「重置已完成」，**再点一次「刷新数据」**，它们就都回来了
（当前页面的数据是生成时定格的一份，光清标记不会当场冒出来）。

**Q：点了「立即更新」失败了**
看控制台最后一行。常见三种：① 连不上 GitHub（要开代理）→ 手动去
[仓库 Releases](https://github.com/dynamor2019/xiaojia-group-board) 下 zip 覆盖；
② `git pull` 报本地有改动 → 说明你改过程序文件，先 `git stash` 或提交再更新；
③ 更新完了页面没回来 → 双击「启动看板.cmd」，数据一点没丢。

**Q：能关掉更新提示吗？**
`config.json` 里把 `update.enabled` 设成 `false` 就彻底不问 GitHub 了。
只想少被问几次的话，把 `update.hours` 改成 `168`（一周一次）。
点提示条右边的 `✕` 是「这一个版本别再提醒」，不是永久关。

**Q：消息比预期少**
默认只留最近 `days` 天、且**没过期**的。头部那行会写「N 条超过 30 天、M 条已过期，已隐藏」，
不是吞了，是被时间窗口挡掉了。

**Q：换电脑 / 换目录后打不开**
看板是用绝对路径生成的，重新点一次「刷新数据」就行。

**Q：能不能抓私聊、抓图片、抓所有消息？**
不能，也刻意不做。只抓群里的 `@所有人` / `@全体成员` 文字消息 ——
既能覆盖「重要通知」这个场景，又把碰到的数据面压到最小。

## 隐私与安全

- 所有数据**只存在你自己电脑上**，没有任何上报接口，代码里也没有埋点
- 解密出来的明文库在 `app/vendor/wcdb-key-tool/decrypted/`，跟你的聊天记录同等敏感，
  `.gitignore` 已排除，**别提交、别分享**
- 密钥文件 `all_keys.json` 同理，泄露等于泄露数据库
- 唯一的网络访问是 NapCat 与你本机之间的 WebSocket（`127.0.0.1`）

---

## 已知限制

- QQ 侧依赖 NapCat，它随 QQ 版本更新偶尔需要升级
- **QQ 侧存在账号被风控的真实风险**（有人遇到过限制登录），微信侧没有这个问题
- 微信侧只支持 4.x 的 WCDB 库格式；3.x 的库结构不同，需要另行适配
- 看板的「已完成」状态存在本机文件里，不跨设备同步
- 自动更新要能连上 GitHub；连不上就只能手动下载覆盖（程序照常能用，只是不提示）
- 退订的群只是不再扫描，历史数据仍留在对应 JSON 里（想看可以手动查）
